# PhotoReady B2C 实施计划说明

## 1. 定位结论

第一阶段不继续把 `CATIA 自动压紧块` 当主项目，也不把精力放到高沟通、高交付的传统 B2B 定制。

主线改为：

- 海外个人用户
- 英文优先
- Web 优先
- 产品类型为 `求职 / 简历 / LinkedIn / 证件照处理工具`
- 收入以美元为主

副线保留：

- `PFMEA` 数字工具包
- 精益模板包
- 办公检查清单包

副线只做标准化下载产品，不做重定制服务。

## 2. 为什么这样做

### CATIA 方向为什么不继续做主线

- 目前没有客户，兴趣也不强。
- 这类产品获客依赖强行业关系和销售周期。
- 对 1 人团队来说，试错成本太高。

解决方案：

- 只保留演示页或资料页。
- 暂时不再占用主开发周期。

### B2B 为什么不作为第一优先级

- B2B 市场竞争激烈，客户要求高，沟通成本大。
- 交付周期长，现金流慢。

解决方案：

- 只保留 `PFMEA / 精益工具` 的标准数字包销售。
- 不接高定制化项目。

### B2C 为什么更适合当前阶段

- 用户群更大。
- 可以直接卖明确结果。
- 更适合英语市场和美元收入。
- 更适合用 Codex 快速做 Web 验证。

## 3. 12 个月分阶段执行

### 第1阶段（2026-07-26 至 2026-08-25）

目标：

- 验证是否有人愿意买。

执行：

- 上线英文官网首页。
- 上线预览页和 waitlist。
- 保留三个卖点：passport、LinkedIn、resume。
- 做 3-5 个 SEO 页面。
- 用 `Lemon Squeezy` 做支付准备。

验收：

- 300 个目标访问。
- 30 个以上邮箱注册。
- 5 个以上付费或强烈预购意向。

### 第2阶段（2026-08-26 至 2026-10-25）

目标：

- 做成可卖的 Web v1。

执行：

- 上传照片。
- 自动清背景。
- 多尺寸裁切。
- 下载导出。
- 支付回执。
- 邮件通知。
- 基础客服 / 退款流程。

验收：

- 注册到付费转化率 3% 以上。
- 退款率低于 8%。
- 至少 3 套尺寸稳定工作。

### 第3阶段（2026-10-26 至 2027-01-25）

目标：

- 稳定放大自然流量和副线收入。

执行：

- 补更多国家尺寸预设。
- 做打印排版、历史记录、重复下载。
- 做 30-50 个 SEO 页面。
- 发布 Product Hunt。
- 同步上架 PFMEA / 精益数字包。

验收：

- 副线收入达到 300-600 美元/月。
- 总月收入接近 1500 美元。

### 第4阶段（2027-01-26 至 2027-07-25）

目标：

- 在已有收入基础上做第二曲线。

执行：

- Web 验证通过后再考虑 macOS / iOS 包装版。
- 建立联盟分销。
- 再决定是否做插件和更多模板。

验收：

- 月收入达到 2550-2850 美元。
- 进入年收入 20 万人民币节奏。

## 4. 销售渠道顺序

按这个顺序推进：

1. 官网落地页
2. Lemon Squeezy 收款
3. SEO 页面
4. Product Hunt
5. Gumroad
6. TikTok / YouTube Shorts / Instagram Reels
7. Reddit / Quora

## 5. 收入结构

建议第 12 个月目标：

- 120 个订阅用户 × 10 美元/月 = 1200 美元/月
- 70 个单次购买用户 × 15 美元 = 1050 美元/月
- PFMEA / 精益数字产品 = 300-600 美元/月

合计：

- 2550-2850 美元/月

## 6. 人员发展预测

- 0-6个月：1个人
- 6-12个月：1名全职 + 1名兼职 / 外包
- 12-24个月：2-3人
- 24-36个月：4-6人
- 36-60个月：7-10人

原则：

- 月稳定收入没到 1 万人民币前，不建议招全职。
- 第一批外包优先设计、内容、客服。

## 7. Codex 的使用方式

所有阶段默认：

- 用 Codex 改首页、定价页、SEO 页面和上传流程。
- 用 Codex 写 Next.js 页面、接口和组件。
- 用 Codex 写产品文案、邮件模板和客服说明。
- 用 Codex 做每周版本更新和回归检查。
