## Practical Use On This Project

Not every agent is needed on every turn, but the site is structured so the relevant roles can be used across the launch:

- `design-ui-designer`
  - visual structure for the independent site
- `design-brand-guardian`
  - brand consistency and future logo rollout
- `engineering-frontend-developer`
  - Next.js page implementation
- `engineering-technical-writer`
  - founder docs, support docs, launch docs
- `marketing-growth-hacker`
  - landing-page conversion focus
- `marketing-seo-specialist`
  - solution pages and internal linking
- `marketing-reddit-community-builder`
  - future launch distribution
- `marketing-linkedin-content-creator`
  - professional audience content
- `sales-offer-lead-gen-strategist`
  - offer structure for export pack and side packs

## Workflow

1. Product context comes from `.agents/product-marketing.md`
2. Site architecture follows `marketingskills` structure
3. Page copy follows `copywriting` and pricing logic
4. Launch checklist follows `launch`
5. Structured data follows `schema`
6. Browser verification uses Playwright only

## Boundary

`agency-agents` is a role library and workflow system, not a one-click site builder. Its practical value here is:

- defining specialist roles
- improving page structure and launch workflow
- giving reusable execution modes for future iterations

That is how it is being used concretely in this repository.
